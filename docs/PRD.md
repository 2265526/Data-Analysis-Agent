# 产品需求文档(PRD)— Data Pipeline Agent

## 1. 背景与目标

企业数据分析需求量大、重复劳动多,业务人员难以直接产出可靠的可视化分析。本平台以**自然语言输入 → 自动化分析报告输出**为核心,通过多智能体协作(Supervisor → Planner → Coder → Executor → Reporter)覆盖需求理解、代码生成、安全执行、报告产出全流程,并支持人机协同审批与全链路审计。

## 2. 业务边界

| 项 | 说明 |
| --- | --- |
| 输入 | 自然语言需求,如"计算近 7 天用户留存率,并与上周对比" |
| 输出 | 含图表的自动化报告(PDF/HTML/Markdown)、执行日志、中间数据 |
| 非目标 | 不直接操作生产库写操作;不替代 BI 大屏搭建;不支持任意代码执行 |

## 3. 核心流程

```
用户需求
  → Supervisor(意图路由)
  → Planner(任务拆解)
  → Coder(代码生成/修复, 向量检索历史代码)
  → Executor(Docker 沙箱安全执行, SQL 只读强制)
  → HumanApproval(大结果集/敏感操作审批, 可选)
  → Reporter(报告生成)
  → 静态报告产物(/static/reports/...)
```

## 4. 功能需求

### 4.1 任务生命周期
- 提交任务 → pending → running →(awaiting_approval)→ completed / failed
- 前端每 2s 轮询 `/api/v1/tasks/{task_id}/status`
- 同一 task_id 幂等,不重复执行

### 4.2 多智能体编排
- **Supervisor**:意图三分类路由(planner / reporter / FINISH)
- **Planner**:结构化 JSON 任务清单(依赖、所需表),支持并行拆解
- **Coder**:生成安全 SQL/Python;结合 Chroma 检索历史成功代码;错误分类(语法→重试,逻辑→重规划),最多重试 3 次
- **Executor**:SQL 只读校验 + Docker 容器隔离(无网络、资源限制、30s 超时),失败降级本地模拟
- **Reporter**:汇总结果,调用图表工具,生成 Markdown/PDF 报告

### 4.3 人机协同
- 大结果集(>10000 行)、重试超限、成本超预算 → 挂起等待审批
- 审批接口 `/api/v1/tasks/{task_id}/approve`,审批人/时间/意见写入审计日志
- 超时未审批默认拒绝,防任务无限挂起

### 4.4 安全与合规
- Prompt 注入防御:输入/系统指令物理隔离(不同 message role)+ 输出校验
- SQL 只读强制:正则黑名单 + 注释剥离,危险语句直接拒绝
- 数据脱敏:手机号/身份证/API Key 掩码,检查点 AES-256-GCM 加密
- 审计:每次请求输入输出、智能体调用路径、审批记录全量落库

## 5. 非功能需求(SLA)

| 指标 | 目标 |
| --- | --- |
| 可用性 | 99.9% |
| 端到端响应 | P95 < 5min(报告任务) |
| 单任务最大时长 | 30min(超时强制终止) |
| 报告数据错误率 | < 0.1% |
| 失败降级 | LLM 不可用→缓存结果;向量库不可用→无检索模式;全失败→人工队列 |

## 6. 评估指标

- 任务拆解准确率、首次代码生成成功率、最终报告可用率
- RAGAs:Faithfulness / Answer Relevancy ≥ 0.7
- Locust 并发基准:10 / 50 / 100 并发下的吞吐与延迟
